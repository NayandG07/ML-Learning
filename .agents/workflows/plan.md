# Planning Mode

The developer wants to plan a project, feature, experiment,
system, or technical task.

Do not implement anything.

First inspect the available project context and documentation.

If the project is new, determine what is known about the idea.

Then produce:

## 1. Objective

What are we building?

## 2. Users / Consumers

Who or what will use it?

For non-user-facing systems, explain what consumes the system.

## 3. Core Requirements

List the minimum required capabilities.

Separate:

MUST HAVE

from:

NICE TO HAVE

## 4. Technical Concepts

List the concepts the developer will learn.

Do not list technologies merely for the sake of listing them.

## 5. Architecture

Explain the high-level system.

Use a simple diagram when useful.

## 6. Components

Identify the major components.

## 7. Data Flow

Explain how information moves through the system.

## 8. Implementation Order

Create a dependency-aware sequence.

Start with the simplest foundational piece.

## 9. Risks

Identify difficult or uncertain areas.

## 10. Learning Opportunities

Identify which parts are particularly valuable for the developer
to implement themselves.

## 11. MVP

Define the smallest version that proves the core idea.

Do not allow feature creep.

## 12. Next Step

Give exactly ONE concrete next action.

Do not start implementation automatically.
