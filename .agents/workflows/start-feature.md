---
description: Start a new feature using a guided learning-first workflow.
---

The developer wants to begin a new feature.

Determine the current project state.

Inspect:

- roadmap
- progress
- git status
- recent changes
- relevant files
- current feature

Determine the next appropriate task.

Do NOT implement the feature automatically.

## Step 1: Understand the Goal

Explain:

- what the feature does
- why the application needs it
- what the user experience should be

## Step 2: Identify Concepts

List the concepts the developer will learn while implementing it.

Keep the list appropriate for the developer's current skill level.

## Step 3: Architecture

Explain:

- where the feature sits in the application
- frontend responsibilities
- backend/server responsibilities if applicable
- database responsibilities if applicable
- external services if applicable

Do not over-engineer.

## Step 4: Files

Identify the files that are likely to be created or modified.

For every important file, explain why it is involved.

Do not modify them yet.

## Step 5: Implementation Plan

Break the feature into small tasks.

Each task should ideally be independently understandable
and implementable.

## Step 6: Start

Give the developer ONLY the first task.

Wait for the developer to implement it.

Do not continue automatically.

## Step 7: Review

After the developer reports completion:

1. Inspect the relevant files.
2. Review the implementation.
3. Identify problems.
4. Ask questions that test understanding.
5. Give hints before giving code.
6. If acceptable, move to the next task.

## Important

The developer is learning.

Do not optimize for speed.

Do not take over implementation.
